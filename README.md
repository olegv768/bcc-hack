# Оценка получателя перевода

Модуль-надстройка для систем банка: перед отправкой перевода оценивает счёт получателя и
останавливает перевод обманутого клиента на счёт дроппера. Встраивается тремя точками, системы
банка переписывать не нужно.

| Точка подключения | Что это | Где лежит |
|---|---|---|
| Сервис оценки получателя | `POST /score`: риск, причины словами, рекомендация — пропустить, предупредить, придержать | [service/](service/) |
| Клиентский модуль | Передаёт признаки «клиент на звонке» и «телефоном управляют удалённо», показывает предупреждение | [sdk/](sdk/) |
| Алерты и выгрузка для аналитика | Алерт в очередь антифрод-аналитика: `GET /alerts` или вебхук; помеченные счета: `GET /flagged` и `GET /flagged.csv` | [service/src/alerts.ts](service/src/alerts.ts), [service/src/store.ts](service/src/store.ts) |

Модель считается локально. Внешние сервисы не вызываются, данные клиентов никуда не уходят;
ИИН, ФИО и номера счетов сервису не нужны — только псевдоним счёта и четыре числа о нём.

## Запуск

Нужен Node.js (проверено на версии 24). Ключи и учётные записи не нужны.

```
npm install
npm run dev
```

Откройте http://localhost:5173 — это стенд. Сервис оценки при этом работает на
http://127.0.0.1:8787.

## Как проверить за две минуты

1. На стенде слева — демонстрационный экран перевода. Получатель «Безопасный счёт», клиент на
   звонке. Нажмите «Перевести».
2. На экране появится окно «Перевод приостановлен» — его показывает клиентский модуль. Справа —
   ответ сервиса: риск, причины и вклад каждого признака в оценку.
3. Выберите получателя «Сестра» — перевод проходит без вопросов. Выберите «Арендодатель» со
   звонком — придёт предупреждение, которое можно прочитать и продолжить.
4. Блок «Панель дежурного фрод-мониторинга»: карточка инцидента с приоритетом, триггерами, суммой и
   контактами клиента; её можно взять в работу и закрыть.
5. Блок «Выгрузка для аналитика»: нажмите «Прогнать 30 случайных переводов», затем скачайте CSV.
6. Внизу страницы — метрики модели.

Запрос к сервису без стенда (команда для bash или Git Bash):

```
curl -X POST http://127.0.0.1:8787/score -H "Content-Type: application/json" -d "{\"recipient\":{\"account_id\":\"tok_1\",\"account_age_days\":4,\"unrelated_senders_7d\":8,\"fast_outflow_share_7d\":0.92,\"shared_device_accounts\":3},\"context\":{\"amount\":450000,\"sender_on_call\":true,\"first_transfer_to_recipient\":true}}"
```

## Что работает

- Сервис оценки: `POST /score`, проверка входных данных, причины и предупреждения на русском,
  казахском и английском, необязательная защита ключом `X-API-Key`.
- Модель: объяснимый бустинг по четырём признакам счёта получателя — возраст счёта, незнакомые
  отправители за 7 дней, скорость вывода денег, общие устройства. Обучение, сравнение с прежней
  моделью и с потолком качества, расчёт метрик — `npm run train`; на данных банка —
  `npm run train -- --data счета.csv`; подбор настроек — `npm run tune`.
- Правило «клиент уже переводил этому получателю»: решение по признакам счёта смягчается на ступень,
  чтобы реже беспокоить людей, которые платят знакомым.
- Память о счёте: подтверждённый аналитиком мошеннический счёт придерживается всегда; счёт с
  отметкой «ложное срабатывание» перестаёт тревожить; переводы от нескольких клиентов на один счёт
  за сутки поднимают решение на ступень.
- Алерты: каждый перевод с рекомендацией «предупредить» или «придержать» сразу попадает в очередь
  аналитика с приоритетом, триггерами, суммой и псевдонимом клиента; доставка вебхуком или опросом.
- Выгрузка: JSON и CSV с фильтрами по времени, риску и рекомендации.
- Клиентский модуль для веба и WebView — работает на стенде.
- Проверка удалённого доступа (AnyDesk и подобные): поле `remote_access_active` в запросе, правило в
  сервисе, переключатель на стенде, код для Android.
- Стенд: экран перевода → сервис → панель дежурного → выгрузка, метрики. Каждый перевод на стенде —
  настоящий запрос к сервису.
- Тесты сервиса: `npm test`.

## Ограничения

- **Метрики получены на синтетических данных.** Типы счетов и их доли — наши допущения. Качество
  на данных банка покажет только проверка на его размеченной истории.
- Сигнал звонка на Android проверен тестовым приложением `sdk/android-test` на одном телефоне
  (Samsung SM-S928B, Android 14) и одном виде звонка; код для iOS написан по документации и не
  собирался.
- Панель дежурного на стенде показывает настоящую очередь алертов, но контакты клиентов в ней вымышлены. Сервис контактов
  не хранит: он отдаёт псевдоним клиента, а контакты подставляет система банка.
- Помеченные счета и алерты хранятся в JSON-файлах — для стенда достаточно, для боевой работы нужно
  хранилище банка.
- Проверка удалённого доступа на Android собирается, но на телефоне с включённой программой
  удалённого доступа не проверялась; список программ нужно сверить и поддерживать.
- Казахские тексты причин и предупреждений нужно вычитать носителю языка.
- Экран перевода и панель дежурного на стенде — демонстрационные, а не интерфейс какого-либо банка.

## Метрики коротко

Сервис целиком (оценка счёта плюс сведения о переводе) на синтетических данных замечает 95 из 100
мошеннических переводов и зря беспокоит 8 из 1000 честных.

Одна оценка счёта, без сведений о переводе, на отложенной выборке (813 дропперов, 39 187 честных счетов):

| Порог | Найдено дропперов | Честных помечено по ошибке |
|---|---|---|
| «Предупредить» | 89,3% | 2,2% |
| «Придержать» | 80,6% | 0,3% |

Прежняя модель (логистическая регрессия) при тех же ложных срабатываниях находила 81,3% и 68,8%;
идеальная модель по этим же признакам — 92,4% и 85,5%, то есть из четырёх признаков выжато почти всё.
Правило «клиент уже переводил этому получателю» сокращает число зря побеспокоенных честных переводов
с 22 до 8 на 1000.

Подробно, с разбивкой по типам счетов и влиянием сигнала звонка — в [docs/METRICS.md](docs/METRICS.md).

## Устройство

```
service/src/   сервис: app.ts (HTTP), model.ts (оценка и решение), alerts.ts (очередь алертов), texts.ts (тексты), store.ts (выгрузка)
service/model/ model.json — веса и пороги модели
ml/            generate.ts (синтетические данные), ebm.ts (модель), train.ts (обучение и метрики), data.ts (CSV), metrics.json
sdk/           клиентский модуль: web/, android/, ios/; android-test/ — приложение для проверки на телефоне
stand/         стенд (React, Vite, D3)
docs/          OpenAPI, интеграция, метрики
```

Команды: `npm run dev` — сервис и стенд; `npm run service` — только сервис; `npm run train` —
переобучить модель и пересчитать метрики; `npm run bench` — замер скорости сервиса; `npm test` — тесты; `npm run build` — проверка типов и
сборка стенда.
