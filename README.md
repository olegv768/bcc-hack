# Оценка получателя перевода

Модуль-надстройка для систем банка: перед отправкой перевода оценивает счёт получателя и
останавливает перевод обманутого клиента на счёт дроппера. Встраивается тремя точками, системы
банка переписывать не нужно.

| Точка подключения | Что это | Где лежит |
|---|---|---|
| Сервис оценки получателя | `POST /score`: риск, причины словами, рекомендация — пропустить, предупредить, придержать | [service/](service/) |
| Клиентский модуль | Передаёт признак «клиент на звонке» и показывает предупреждение | [sdk/](sdk/) |
| Выгрузка для аналитика | Помеченные счета с причинами: `GET /flagged` (JSON) и `GET /flagged.csv` (файл) | [service/src/store.ts](service/src/store.ts) |

Модель считается локально. Внешние сервисы не вызываются, данные клиентов никуда не уходят;
ИИН, ФИО и номера счетов сервису не нужны — только псевдоним счёта и четыре числа о нём.

## Запуск

Нужен Node.js (проверено на версии 24). Ключи и учётные записи не нужны.

```
npm install
npm run dev
```

Откройте http://localhost:5173 — это стенд. Сервис оценки при этом работает на
http://127.0.0.1:8787.

## Как проверить за две минуты

1. На стенде слева — условная заглушка экрана перевода. Получатель «Безопасный счёт», клиент на
   звонке. Нажмите «Перевести».
2. В заглушке появится окно «Перевод приостановлен» — его показывает клиентский модуль. Справа —
   ответ сервиса: риск, причины и вклад каждого признака в оценку.
3. Выберите получателя «Сестра» — перевод проходит без вопросов. Выберите «Арендодатель» со
   звонком — придёт предупреждение, которое можно прочитать и продолжить.
4. Блок «Выгрузка для аналитика»: нажмите «Прогнать 30 случайных переводов», затем скачайте CSV.
5. Внизу страницы — метрики модели.

Запрос к сервису без стенда (команда для bash или Git Bash):

```
curl -X POST http://127.0.0.1:8787/score -H "Content-Type: application/json" -d "{\"recipient\":{\"account_id\":\"tok_1\",\"account_age_days\":4,\"unrelated_senders_7d\":8,\"fast_outflow_share_7d\":0.92,\"shared_device_accounts\":3},\"context\":{\"amount\":450000,\"sender_on_call\":true,\"first_transfer_to_recipient\":true}}"
```

## Что работает

- Сервис оценки: `POST /score`, проверка входных данных, причины и предупреждения на русском,
  казахском и английском, необязательная защита ключом `X-API-Key`.
- Модель: логистическая регрессия по четырём признакам счёта получателя — возраст счёта,
  незнакомые отправители за 7 дней, скорость вывода денег, общие устройства. Обучение и расчёт
  метрик — `npm run train`.
- Выгрузка: JSON и CSV с фильтрами по времени, риску и рекомендации.
- Клиентский модуль для веба и WebView — работает на стенде.
- Стенд: заглушка перевода → сервис → выгрузка, метрики.
- Тесты сервиса: `npm test`.

## Ограничения

- **Метрики получены на синтетических данных.** Типы счетов и их доли — наши допущения. Качество
  на данных банка покажет только проверка на его размеченной истории.
- Сигнал звонка на Android проверен тестовым приложением `sdk/android-test` на одном телефоне
  (Samsung SM-S928B, Android 14) и одном виде звонка; код для iOS написан по документации и не
  собирался.
- Помеченные счета хранятся в одном JSON-файле — для стенда достаточно, для боевой работы нужно
  хранилище банка.
- Казахские тексты причин и предупреждений нужно вычитать носителю языка.
- Стенд — условная заглушка, а не интерфейс какого-либо банка.

## Метрики коротко

На отложенной выборке из синтетических данных (813 дропперов, 39 187 честных счетов):

| Порог | Найдено дропперов | Честных помечено по ошибке |
|---|---|---|
| «Предупредить» | 81,3% | 2,2% |
| «Придержать» | 68,8% | 0,3% |

Подробно, с разбивкой по типам счетов и влиянием сигнала звонка — в [docs/METRICS.md](docs/METRICS.md).

## Устройство

```
service/src/   сервис: app.ts (HTTP), model.ts (оценка и решение), texts.ts (тексты), store.ts (выгрузка)
service/model/ model.json — веса и пороги модели
ml/            generate.ts (синтетические данные), train.ts (обучение и метрики), metrics.json
sdk/           клиентский модуль: web/, android/, ios/; android-test/ — приложение для проверки на телефоне
stand/         стенд (React, Vite, D3)
docs/          OpenAPI, интеграция, метрики
```

Команды: `npm run dev` — сервис и стенд; `npm run service` — только сервис; `npm run train` —
переобучить модель и пересчитать метрики; `npm test` — тесты; `npm run build` — проверка типов и
сборка стенда.
