# Метрики

Все цифры получены командой `npm run train` и лежат в [ml/metrics.json](../ml/metrics.json).
Зерно генератора фиксировано, повторный запуск даёт те же цифры.

## На чём считали

**Данные синтетические.** Открытых наборов с нужными признаками (связи отправителей, общие
устройства, скорость вывода) мы не нашли, поэтому счета создаёт генератор
[ml/generate.ts](../ml/generate.ts). Типы счетов, их доли и распределения признаков — наши
допущения, а не статистика банка.

Цифры ниже показывают, как модель разделяет заложенные нами типы счетов. Качество на реальных
данных банка они не предсказывают: его покажет только проверка на размеченной истории банка.

- 200 000 счетов, дропперов 2%.
- 60% — обучение, 20% — подбор порогов, 20% — отложенная выборка. Все метрики — по отложенной
  выборке: 813 дропперов и 39 187 честных счетов, которых модель не видела.
- Модель — логистическая регрессия по четырём признакам счёта получателя.

Чтобы задача не была тривиальной, в генератор заложены трудные случаи:

| Честные, похожие на дропперов | Дропперы, похожие на честных |
|---|---|
| Продавцы, фрилансеры, сборы: много незнакомых отправителей | Купленный старый счёт: возраст не выдаёт |
| Клиенты, которые сразу уводят деньги в другой банк | Счёт используют впервые: истории почти нет |
| Недавно открытые счета | Маскируется под обычного клиента |
| Семья или небольшое дело на одном устройстве | |

## Счета: сколько дропперов находим и сколько честных беспокоим

| Порог | Найдено дропперов | Честных помечено по ошибке | Доля дропперов среди помеченных |
|---|---|---|---|
| «Предупредить» (риск ≥ 0,80) | 81,3% | 2,2% | 43,4% |
| «Придержать» (риск ≥ 0,95) | 68,8% | 0,3% | 81,2% |

Площадь под ROC-кривой — 0,979.

Пороги подобраны на отдельной выборке так, чтобы среди честных счетов выше порога «предупредить»
было 2%, выше порога «придержать» — 0,3%. Доля дропперов среди помеченных зависит от того, сколько
дропперов среди всех счетов; у нас это допущение — 2%.

### По типам счетов

Доля счетов каждого типа выше порога.

| Тип счёта | Счетов | Предупредить | Придержать |
|---|---|---|---|
| **Дропперы — доля найденных** | | | |
| Свежий счёт под вывод денег | 429 | 100,0% | 99,8% |
| Купленный старый счёт | 198 | 78,8% | 46,5% |
| Счёт используют впервые | 100 | 63,0% | 34,0% |
| Маскируется под обычного клиента | 86 | 15,1% | 5,8% |
| **Честные — доля помеченных по ошибке** | | | |
| Обычный клиент со старым счётом | 28 188 | 0,0% | 0,0% |
| Недавно открыл счёт | 3 990 | 5,0% | 0,5% |
| Продавец, фрилансер, сбор денег | 3 135 | 9,9% | 2,4% |
| Сразу уводит деньги в другой банк | 2 731 | 11,6% | 1,1% |
| Несколько счетов на одном устройстве | 1 143 | 1,6% | 0,1% |

Что из этого следует:

- Слабое место — дропперы без истории и те, кто маскируется под обычного клиента. По четырём
  признакам счёта их почти не отличить; здесь помогает сигнал звонка (см. ниже).
- Ложные срабатывания сосредоточены у продавцов и у клиентов, быстро уводящих деньги. Для них
  банку стоит добавить свои признаки, например отметку «счёт предпринимателя».
- Групп мало (86–429 дропперов каждого типа), поэтому доли по типам точны до нескольких
  процентных пунктов.

## Переводы: что даёт сигнал звонка

Здесь оценивается сервис целиком: модель и правила по обстоятельствам перевода. На каждый счёт
дроппера из отложенной выборки создано 20 мошеннических переводов (16 260), на каждый честный
счёт — один честный перевод (39 187).

| Переводы | Без сигнала звонка | С сигналом звонка |
|---|---|---|
| Мошеннические: придержано | 68,8% | 77,3% |
| Мошеннические: предупреждение | 12,5% | 15,0% |
| Мошеннические: пропущено | 18,7% | 7,7% |
| Честные: придержано | 0,3% | 0,3% |
| Честные: предупреждение | 1,8% | 1,9% |

**Эта таблица зависит от допущений, которые мы не можем проверить без данных банка:**

| Допущение | Мошеннический перевод | Честный перевод |
|---|---|---|
| Клиент на звонке | 70% | 2% |
| Первый перевод этому получателю | 95% | 25% |
| Сумма относительно обычной (медиана) | в 5 раз больше | такая же |

Вывод, который от точных цифр не зависит: сигнал звонка ловит часть переводов на счета, которые
по признакам счёта выглядят чистыми. Насколько большую часть — банк узнает после подключения
клиентского модуля.

## Как проверить на данных банка

1. Собрать выборку счетов с четырьмя признаками и отметкой «дроппер / не дроппер».
2. Подставить её вместо `generateAccounts` в [ml/train.ts](../ml/train.ts) — остальной расчёт
   (обучение, пороги, метрики) не меняется. Готового загрузчика файлов в проекте нет.
3. Выбрать пороги по допустимой доле ложных срабатываний (`TARGET_FPR` в том же файле).
